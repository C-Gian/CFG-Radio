# assets/

**Smoke-test audio only. Not music, not a demo track, not user facing content.**

Three synthetic sine sequences, encoded as Ogg/Opus 48 kHz stereo — exactly the
format Discord voice consumes. They are deliberately easy to tell apart by ear so
queue order, auto-next, `/skip` and `/stop` can be verified during a manual test.

| File              | Length | Sound                                    |
| ----------------- | ------ | ---------------------------------------- |
| `arpeggio.opus`   | 8s     | A4 → C#5 → E5 → A5, two seconds per note |
| `ascending.opus`  | 6s     | C major scale going up, eight notes      |
| `descending.opus` | 6s     | the same scale going down                |

Everything is generated by FFmpeg's `sine` source, so there is no copyrighted
material involved and the output is reproducible. The recipes (notes, note
length, duration) live in `src/audio/local-catalog.ts`, which is also what the
player uses to resolve a track — catalog and files cannot drift apart.

Regenerate them with:

```
npm run assets:generate
```

The generator lives in `tools/generate-local-assets.ts` and needs a system FFmpeg
built with libopus (`npm run diagnostics:voice` verifies that, and checks that
every asset still decodes through the playback pipeline).
